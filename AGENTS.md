# AGENTS.md

Instructions for AI coding agents working in this repository. People follow the same rules; see [CONTRIBUTING.md](CONTRIBUTING.md) for the workflow.

## Project

A small group-chat client built with React 19, TypeScript and Vite. It lists messages, sends new ones, checks for new ones every second and shows typing dots. By default the API (`/messages` and `/typing`) is answered inside the browser by a mock API (MSW) in `src/mocks`, so the app runs with no backend. Browsers stop idle service workers and a restarted MSW worker forgets the tab, so `src/services/api.ts` turns mocking back on (`reactivateMockApi` in `src/mocks/browser.ts`) and retries once when a mock request gets a non-JSON answer. Setting `VITE_API_URL` points it at a real one.

## Commands

| Task                       | Command                                      |
| -------------------------- | -------------------------------------------- |
| Install                    | `npm install`                                |
| Run locally                | `npm run dev`                                |
| Unit and integration tests | `npm test`                                   |
| One test file              | `npx vitest --run src/path/to/file.test.tsx` |
| Tests with coverage        | `npx vitest --run --coverage`                |
| End-to-end tests           | `npm run e2e`                                |
| Lint                       | `npm run lint`                               |
| Format                     | `npm run format`                             |
| Type-check and build       | `npm run build`                              |

`npm run test:coverage` and `npm run test:ui` start watch mode and never exit. Use the commands above instead.

## Before you say a task is done

1. `npm run lint` passes.
2. `npm test` passes, including tests you added for the change.
3. `npm run build` passes (it type-checks first).
4. If you touched the chat page, the API layer or the mock API, `npm run e2e` passes.

Report what you ran and the result. If something fails and you can't fix it, say so; don't hide it.

## Structure

```text
e2e/
  fixtures/       Network stubs for the end-to-end tests
  pages/          Page object for the chat page
  tests/          Playwright specs
src/
  components/     MessageList, MessageInput, WebSocketToggle
  constants/      API paths, chat settings, shared styles
  mocks/          In-browser mock API: MSW handlers, localStorage store, seed data
  pages/          ChatPage
  services/       api.ts (HTTP client) and messageService.ts (endpoints)
  stores/         messageStore (Zustand)
  types/          Shared types
  utils/          Error and message helpers
  routes.tsx      Router configuration
```

## Rules

- **Types.** No `any`, no `@ts-ignore`, no non-null assertions to silence errors.
- **Layers.** Components talk to the store, the store talks to `messageService`, and only `src/services` makes HTTP requests. Don't call `fetch` from a component.
- **State.** Zustand, with a selector per subscription.
- **Mock API.** It must match the contract in the README: same paths, query parameters, validation and ordering. Change `handlers.ts` and `handlers.test.ts` together. The store falls back to memory when `localStorage` is blocked; keep that working.
- **Errors.** Every failed request produces a visible message. Nothing may crash the page.
- **UI.** Material UI components. Shared style values live in `src/constants/styles.ts`.
- **Routing.** Use the router. A plain `href` skips the base path and breaks the GitHub Pages deployment.
- **Style.** Prettier decides formatting. Components are PascalCase files; other files are camelCase. Import through the `@/` alias.
- **Language.** Code, comments and documentation are in English.

## Tests

- Vitest and React Testing Library. Test files are `__tests__/*.test.ts(x)` next to the code.
- Query by role and label. Test what the user sees, not implementation details.
- Playwright specs use the page object in `e2e/pages/ChatPage.page.ts`. Keep selectors there. The network is stubbed in `e2e/fixtures/mockAPI.ts`, so the specs don't depend on the mock API's random replies.
- Write the implementation first, then its tests, in the same change.

## Guardrails

- Don't edit `public/mockServiceWorker.js`; it is generated by MSW.
- Don't commit `.env.local`, secrets or generated reports (`coverage/`, `playwright-report/`, `test-results/`).
- Don't add a dependency without a reason recorded in `architecture-decision-record.md`.
- Don't push to `main`. Work on a branch and open a pull request.
- Don't skip the pre-commit hook (`--no-verify`).
- Keep changes small. If a request conflicts with these rules, say so and propose an alternative instead of complying silently.

## How AI is used in this project

AI coding agents are used for exploration, scaffolding tests and documentation. Every change is read, run and tested by a person before it is merged, and CI runs the lint, unit, end-to-end and build steps on every pull request.
